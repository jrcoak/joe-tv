## Report structure

1. Assignment, exact baseline/HEAD, spec revision, branch, worktree, inspected components.
2. Existing strengths and accepted behavior worth preserving.
3. Findings with file/symbol evidence, impact, confidence, and verification status.
4. Two or three improvement proposals: viewer situation, behavior, benefit, prior implementation, effort, dependencies, smallest experiment, success criterion.
5. Ownership boundaries, shared-file needs, documentation discrepancies, and outstanding questions.
6. Checks actually run and results, pending simulator/device/live-service validation.

Commit only the owned report. Send PM one completion handoff with commit ID and results, then idle. Do not run an endless wait or start another assignment.
