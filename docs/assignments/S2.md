## Cache acceptance

Read `docs/sprints/S1-S2-secops.md` for the complete public-method lifecycle matrix. Validate both network and disk candidates before use/write; wrong-root XML is invalid, `<tv/>`, zero matching programs and valid empty sports events are valid. On accepted 200 validate then atomic write then update/remove ETag and record success; a 200 without a validator removes the old one. Only send If-None-Match with usable cached bytes. A 304 revalidates only a usable cached body; missing/corrupt cache stays recoverable via the next eligible unconditional request. Preserve current typed malformed/status errors and the five-minute attempt floor; no automatic retry loops or new silent stale-result policy. Failed reads/throttled/offline reads do not advance success; attempts advance only on dispatch. A legacy cache with unknown successful time must not fabricate current freshness.

Tests must assert outcomes plus exact retained/replaced bytes, validators, success/attempt time, request counts/headers and recreation/persistence, including invalid-after-valid, valid empty, missing/corrupt cache, 304, transport fallback, untagged replacement, HTTP status and isolated write failure. Use an intercept-all ephemeral URLProtocol, no default cache/cookies and no real credentials. Production defaults retain existing initialization behavior; fully injected test dependencies must avoid real configuration/defaults/cache reads. Clean up only owned temporary resources. The separate AppModel merged-window Date() freshness limitation stays explicitly documented.

## Parser performance acceptance

Read `docs/research/guide-parser-performance.md`. Formatter reuse alone did not establish a gain. Reusing repeated timestamp parse results within one XMLTV document did (about 75–80 ms median versus highly variable 2–13 s baseline medians on a controlled synthetic input, uncontrolled host load). Keep cache local to one parser delegate/document; do not introduce global shared mutable DateFormatters or cross-request state. Preserve all four accepted timestamp formats, signed offsets, station filtering, ordering and start/end boundary behavior. Add meaningful equivalent-output tests with mixed formats/offsets, malformed values and independent/repeated parses, not merely a count assertion. Valid empty and unrelated well-formed XML must be distinguished. A unique-timestamp document is an important correctness case; benchmark benefit is workload-dependent.

PM's `scripts/benchmark-guide-parser.sh` is read-only to Services. Run it against final source only after source correctness tests; report exact source/config/data and samples without translating host parsing speed into TV input latency. Benchmark compilation can be costly. Coordinate expensive compilation with PM/QA; no simulator/profiler/media operations are assigned to Services.
