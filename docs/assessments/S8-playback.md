# S8 Playback — sanitized failure support codes

September 27, 2026. Assignment `S8`, release baseline `29fb03c121fde354d7c11c8899e088fa887ba533`, application source `ff68e4b3f625d494b337bcded05efe26fa2a14b8`, branch `codex/s8-playback-diagnostics`. Playback owns only the new pure failure classification in `Models.swift`, `PlaybackSession.handlePlayerStatus`, its dedicated offline test and runner, and this report.

When `AVPlayerItem.status` becomes `.failed`, the player now classifies a bounded error chain and the latest error-log event into a short, privacy-safe support code. Exact allowlisted domains are reduced to `URL`, `AVF`, `CM`, `OS`, or `HTTP`; numeric values are bounded and at most two observations appear. The latest allowlisted error-log observation is always retained, and a specific nested URL/HTTP/AVFoundation cause outranks a generic CoreMedia wrapper. Known cases receive a concise cause such as authorization, network, secure connection, unavailable stream, server failure, unsupported format, protected content or media load failure. Unknown evidence retains the generic playback message and uses `P-UNKNOWN`.

The classifier follows at most four `NSUnderlyingErrorKey` links and stops on repeated object identity. It never incorporates URLs, URI/path/query values, `userInfo` strings other than following the underlying-error object, localized descriptions, arbitrary domain names, headers, response bodies, server addresses, session identifiers, FairPlay identifiers or key data. The DEBUG print now contains only the sanitized support code. The existing 20-second preparation timeout remains separate and keeps its existing message.

This change does not add network requests, media probes, logging infrastructure, retries, alternate-feed selection or fallback. AVPlayer/asset construction, HLS/FairPlay behavior, captions, settings, navigation and project configuration are unchanged. It improves the evidence available from the already-existing failure overlay; it does not repair an unidentified transport failure by itself.

`sh scripts/test-playback-failure.sh` passes 89 focused checks. Coverage includes known URL network/timeout/secure-connection cases, named AVFoundation format/protected-content/server cases, HTTP authorization priority, preservation of latest HTTP evidence after two wrappers, a nested URL cause beneath generic AVFoundation/CoreMedia wrappers, CoreMedia and OSStatus categorization, unknown errors, observer fallback, bounded numeric output, a self-cycle, a known error beyond the depth limit, and malicious URL/token/header/body/domain strings that must not appear in either message or support code. Complete tvOS source type-check, `xcrun swiftc -frontend -parse SeasonsTV/Models/Models.swift Tests/PlaybackFailureSmoke.swift`, and `git diff --check` also pass. The existing FairPlay deprecation warning is unchanged.

Per assignment, no Xcode build, simulator, device, provider request, stream, DRM validation, installation, deployment or release ran. A real failure can still yield `P-UNKNOWN` when AVFoundation supplies no allowlisted error evidence. This patch intentionally does not collect FairPlay stage-specific evidence or inspect response content because those require separate ownership and validation. PM/QA own integration and any serialized physical-device reproduction after runtime coordination. Competitor comparison does not apply to this incident diagnostic because it changes failure evidence for an existing playback path rather than product behavior.
