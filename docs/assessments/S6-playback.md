# S6 Playback — caption defaults and quiet-volume automation

September 20, 2026. Original Joe-TV baseline `46256bc`, branch `codex/joe-tv-playback-s6`. Scope is `PlaybackSession`, full-screen caption controls, a pure policy test and this report. Player, FairPlay, live-edge, preferred audio, preview ownership and provider code remain intact.

Every real `PlaybackSession` now temporarily holds AVPlayer automatic media selection while its legible group loads, explicitly selects Off when that group permits an empty selection, then restores automatic selection. This prevents inherited automatic captions from flashing at startup while retaining AVFoundation’s automatic audible-track preferences. Apple documents that `AVPlayerItem.select(nil, in:)` overrides automatic selection only for that group until automatic selection is explicitly requested again ([selection API](https://developer.apple.com/documentation/avfoundation/avplayeritem/select%28_%3Ain%3A%29), [criteria API](https://developer.apple.com/documentation/avfoundation/avplayer/appliesmediaselectioncriteriaautomatically)). Content whose legible group forbids empty selection cannot truthfully offer Off; the UI omits that action.

The full-screen caption dialog remains available even before tracks are found. It offers manual tracks plus persistent automatic choices: Off, Muted/0%, 5%, 10%, and 20%. The PM-recommended default is 10%. Captions remain Off above the selected entry threshold; a two-point hysteresis band prevents toggling near the boundary. Automatic captions prefer a CC/SDH option, then the first available legible option. When volume rises or the signal becomes unknown, an automatically selected track returns to Off. A manually selected track is never replaced. Manual Off suppresses re-enabling until that quiet episode ends.

Only `PlayerSessionView` starts the volume observer, so guide/Home previews never receive automatic caption decisions. Disappearance removes observation and supplies an unknown signal, ending any automatic episode. No app mute control was added because the existing player has no mute control that would provide stronger evidence.

Apple documents `AVAudioSession.outputVolume` as a KVO-observable system volume from 0 to 1 ([API](https://developer.apple.com/documentation/avfaudio/avaudiosession/outputvolume)). The tvOS 26.5 SDK marks `AVAudioSession.isOutputMuted` unavailable on tvOS, and no public AVPlayer automatic-subtitles-on-mute property was found. Apple TV’s own Show When Muted feature warns that infrared-controlled TV volume is unsupported ([Apple TV guide](https://support.apple.com/guide/tv/atvb7d97de8b/tvos)). Joe-TV therefore treats only finite in-range `outputVolume` samples as evidence, labels the control as a device-volume threshold, and tells viewers that TV/receiver volume may be invisible. It does not infer HDMI, receiver or infrared state.

`sh scripts/test-caption-policy.sh` passes 25 focused checks. It covers unknown/invalid signals, all boundary classes, hysteresis, quiet lifecycle, manual track retention, manual-Off episode suppression and mode changes. The existing FairPlay deprecation warning is unchanged. No simulator, provider, media, device, installation or project edit ran. PM/QA still need the existing caption fixture to verify no startup flash, rendered track changes, focus/Back, persistent choice and lifecycle; physical Apple TV must check actual route reporting and external TV/receiver mute limits.
