# S7 Playback — refresh dynamic football links at selection

September 25, 2026. Assignment `S7-FIX`, baseline/spec revision TEAM-4 at Joe-TV `234072927fea47a842921a4d66d20e983dbc89a7`, branch `codex/joe-tv-playback-s7`. Playback owns this bounded correction in `SeasonsClient` and `AppModel`, its focused offline test, runner and this report. No player, model, view, project, provider, service, credential, runtime or release file changed.

Dynamic football direct-HLS options no longer pass their catalog-time signed URL straight to `AVPlayer`. When a viewer selects one, `AppModel.makePlaybackSession(for:item,option:)` asks the existing authenticated `SeasonsClient` for one fresh football metadata snapshot: an explicit GET of the current Player page with `.reloadIgnoringLocalCacheData` supplies the direct-stream template, then the current week and game-list metadata rebuild the options. The shared client already has no URL cache and uses the same reload policy; the explicit request makes this signed-template requirement local and testable. There is no media request or speculative playback probe in this refresh.

The refreshed selection requires one exact stable event ID and one exact semantic option identity. The option identity consists of its normalized broadcast role and live/DVR mode, so provider ordering and ephemeral option IDs cannot redirect the selection. Home, Away, National, International, US, Spanish, radio and alternate roles are distinguished; arbitrary labels receive a deterministic normalized identity. The old signed URL is not an identity input. If the event disappeared, the chosen feed disappeared, or duplicate candidates make the result ambiguous, playback stops with a specific refresh-and-reselect message. It does not borrow another event or feed.

Only direct HLS options on `dynamic|football|…` items enter this path. Existing resolved-request, DRM, baseball, ESPN+, static catalog and live-channel routes keep their prior behavior. If fresh metadata represents the same event/feed/live-DVR identity with a provider request instead of a direct link, the current request is resolved through the existing path. Live-edge policy remains derived from the selected event exactly as before.

`sh scripts/test-football-playback-refresh.sh` passes 35 focused offline checks. Parsed old and fresh fixtures prove that reordered Home/Away and live/DVR options receive the fresh signature and key, while exact event/feed identity is retained. The suite also verifies the uncached GET request, rejects a same-title different event, a missing feed and duplicate semantic feeds, distinguishes National from International, avoids refreshing request and non-dynamic routes, and verifies a same-feed transition to current request metadata. Schedule enrichment and Sports consolidation retain the `dynamic|football|…` ID, so the normal Sports card still enters this refresh. `fantasyNFLScoreItems` copies that playable item's ID and options; a matching projection fixture verifies the Fantasy card also enters it. The existing FairPlay deprecation warning is unchanged.
