## 2. Strengths and accepted behavior to preserve

- Metadata failures are separate from stream resolution. `AppModel.refreshSportsSchedule` retains the previous snapshot on failure; `refreshEPG` has an explicit cached failure state. Schedule-only events stay `.unavailable` for playback. Improvements should strengthen these existing boundaries.
- The directory uses stable provider identities and explicit station mapping. `XMLTVParser` accepts only allowed stations also declared in the XML document and filters by absolute overlap; it never guesses from display names.
- Sports supports 26 canonical categories, legacy preference migration, studio exclusion, Live/Upcoming filtering, a 15-minute pregame availability rule, and distinct baseball feed options. `SportsScheduleEnricher` checks provider dates where available; `Tests/ParserSmoke.swift:414–480` covers games across successive days.
- `AppModel.rebuildConsolidatedSportsItems` caches consolidation when sources change. Detail work uses two-item batches and focus debounce; browsing should remain independent of network completion.
- Quick Switch stores `PlaybackTarget` identities and resolves the selected target again. Favorites and disabled channels remain separate persisted choices. `adoptNewDefaultFavoritesIfNeeded` is version-gated, protecting a later intentional NHPBS removal.
- `SportsEventDetailDecoder` verifies provider/event/sport/league identity before caching a detail response. This is a useful existing pattern for validating other cache writes.

## 3. Findings

### S1 — Invalid success responses can replace the last usable guide/schedule cache

**Observation:** `SeasonsTV/Networking/XMLTVGuideProvider.swift:202`, `currentGuideData`, writes every nonempty HTTP 200 body at line 227 and updates its ETag before `loadGuide` parses XML. `currentSportsScheduleData` does the same at line 278 before `loadSportsSchedule` decodes JSON at line 126. Atomic writes prevent torn files, not invalid documents. A subsequent call inside the five-minute attempt window reuses that file. HTTP errors represented by `EPGServiceError` bypass the transport-error disk fallback.

**Impact/inference:** A malformed 200 can destroy the disk copy advertised as last-known-good; after restart the prior in-memory fallback is gone. This does not itself disable playback. A server 503 is also handled differently from a network timeout, so fallback behavior needs an explicit policy, including separate treatment of authorization failures.

**Confidence/status:** High confidence in source ordering; runtime incident and prevalence unverified. **Dependency/next experiment:** Services plus QA; use isolated URLSession/cache/defaults fixtures with valid → malformed 200 → restart → 304, and timeout/401/404/503 sequences. Accept only validated replacements; preserve the prior cache and matching ETag when validation fails; recover on a later valid response; respect the polling floor. No backend change is needed for the first experiment.

### S2 — A partial guide refresh can discard usable listings from the failed source

**Observation:** `AppModel.refreshEPG` (`SeasonsTV/App/AppModel.swift:904`) retains the previous merged window only when all providers fail. If one provider succeeds, lines 966–981 rebuild programs and channel mappings solely from successful results. `VeryLocalClient.loadGuide` (`SeasonsTV/Networking/VeryLocalClient.swift:216`) additionally drops failed station results with `try?` and reports success if any station succeeds. Its mapping list still includes all requested stations.

**Impact/inference:** An XMLTV failure alongside a successful Very Local refresh can erase otherwise usable cached S4U/PBS listings; the reverse is also possible. A single Hearst station can look like an empty schedule without a partial-failure signal. Guide requests are sequential between the provider groups, so slow Hearst results delay starting the XMLTV request even when that service is healthy.

**Confidence/status:** High source confidence; UI timing and failure presentation not measured. **Dependency/next experiment:** PM allocation of `AppModel.refreshEPG` plus Services/QA fixtures. Start from two populated sources, fail one, then recover. Success: preserve still-relevant cached programs and station mappings for the failed source, merge the healthy result, mark only affected data as stale, and keep Select-to-play usable. Expired programs must not be relabeled as current.

### S3 — Event consolidation can merge distinct games, and undated enrichment remains ambiguous

**Observation:** `SeasonsTV/Models/Models.swift:514`, `SportsEventGuidePolicy.describeSameEvent`, accepts equal item IDs before any date test; otherwise matching team titles with start times less than six hours apart merge, without checking distinct canonical event IDs or league/category equality. Without both start times, a missing provider date permits a match. `SeasonsTV/Networking/HTMLCatalogParser.swift:1416`, `SportsScheduleEnricher.playbackItem`, checks titles then returns true when the provider date is unavailable.

**Impact/inference:** A same-team doubleheader four hours apart can collapse into one card with mixed playback options. Reused IDs across dates or an undated provider row can also attach to an unintended event. Existing successive-day fixtures do not cover these conditions; this is not evidence that a current live game was misrouted.

**Confidence/status:** High confidence in merge predicates; medium confidence in upstream occurrence. **Dependency/next experiment:** Services, Playback review, and explicit PM ownership of `SeasonsTV/Models/Models.swift`/`Tests/ParserSmoke.swift`. Synthetic fixtures should cover a true S4U/ESPN+ duplicate, two distinct same-team games, reused IDs across dates, missing dates, and matching titles in different competitions. Success: true duplicates combine, distinct events remain separate, ambiguous options do not silently acquire an asserted game identity, and Home/Away/National options stay attached to the correct game.

### S4 — Freshness is available in some models but is not consistently carried to the viewer

**Observation:** `refreshEPG` stamps the merged window with `Date()` rather than preserving source age. `XMLTVGuideProvider.loadSportsSchedule` records refresh time even when decoding a throttled/transport-fallback cache; `SportsScheduleSnapshot.generatedAt` remains the original publication timestamp. `AppModel.prefetchSportsEventDetails`/`focusSportsEvent` skip an identity once its detail is present, and no consumer checks `SportsEventDetail.expiresAt` (`SeasonsTV/Models/Models.swift:847`). `refreshFantasyMatchup` and `refreshFantasyNFLScoreboard` retain old values on errors. `FantasyScorebugContent` (`SeasonsTV/Views/PlayerScreen.swift:1025`) derives its LIVE indication from game/starter state without consulting refresh failure or data age.

**Impact/inference:** Old descriptions, schedules, and scores can remain useful, but the viewer cannot reliably distinguish cached information from a successful fresh update. A retained in-progress status may continue to look live after updates stop. No prolonged outage was observed.

**Confidence/status:** High source confidence; viewer comprehension untested. **Dependency/next experiment:** Services freshness contract, Design wording, App/Playback rendering, QA fake-clock scenarios. Keep separate publication, last-success, and last-attempt times; a failed attempt or 304 must not imply a newly published game record. Validate stale/refreshing/recovered states without adding a technical dashboard or changing the publisher architecture.

### S5 — Unknown category and malformed payload handling can hide events silently

**Observation:** `HTMLCatalogParser.parseESPNPlusEvents` (`SeasonsTV/Networking/HTMLCatalogParser.swift:197`) returns an empty list for invalid/unrecognized JSON and discards an item when the string-based classifier returns nil at line 233. That classifier returns nil both for unknown sports and excluded studio programs, whereas the `MediaItem` classifier has an Other fallback. `AppModel.loadESPNPlusSportsWindow` can therefore mark an empty successful parse as loaded. The wrapper classifier also retains a generic `college` → `college-football` fallback (`SeasonsTV/Models/Models.swift:380`); the HTML source section currently aliases `ncaaf`, but the shared model does not preserve that provenance.

**Impact/inference:** A new upstream event category may disappear instead of appearing under Other, contrary to TEAM-1's unmatched-event rule. Schema drift can look like a quiet day. An unclassified generic College item may inherit Football without sport evidence. Existing taxonomy fixtures cover known examples and studio exclusion, not unknown-event fallback.

**Confidence/status:** High source confidence; no new upstream payload was sampled. **Dependency/next experiment:** Services plus PM-owned classifier/tests allocation. Distinguish excluded programming, unclassified valid event, valid empty day, and invalid payload. Success: unknown valid events reach Other; studio/replay exclusions and all 26 saved categories remain intact; malformed data produces a recoverable partial failure while valid prior listings remain available. Preserve legacy preference migration independently of runtime classification.

### S6 — Provider schema resilience needs targeted fixtures, not broader live probing

**Observation:** `HTMLCatalogParser.parseCatalog`, `parseDRMChannels`, and `parseDRMConfiguration` depend on HTML classes, script shapes, and regex extraction; FairPlay parsing limits its selected block to 8,000 characters. Dynamic supplements in `SeasonsClient.loadCatalog`/`loadCurrentBaseballEvents` use optional failure handling. `loadLiveChannels` awaits DRM and legacy HTML as a throwing pair, so a non-authentication failure in one request loses the other request's successfully fetched channels for that refresh.

**Impact/inference:** Layout/schema changes or one unavailable provider page can reduce coverage with limited diagnosis. The active FairPlay content-ID and domestic-proxy parsing fixes must be preserved; replacing the player is unrelated to this risk.

**Confidence/status:** High confidence in dependencies; failure rates unknown. **Dependency/next experiment:** Services owns sanitized, synthetic parser fixtures; Playback reviews descriptor outcomes; SecOps reviews any new diagnostics. Test reordered attributes, missing optional sections, malformed dynamic payloads, and one failed channel page. Success: distinguish empty from invalid/partial results, retain valid unaffected sources, and never log credentials, signed URLs, or license material. `Tests/ParserSmoke.swift` already offers a substantial starting point; it is not HTTP/cache orchestration coverage.
